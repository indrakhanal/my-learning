# 03 — Database & Schema

## Technology
- **ORM**: Prisma 5 (`@prisma/client` + `prisma`)
- **Database**: PostgreSQL 16+
- **Schema file**: `backend/prisma/schema.prisma`
- **Migrations**: `backend/prisma/migrations/`
- **Seed**: `backend/prisma/seed.ts`

## Migration Workflow

```powershell
# 1. Edit backend/prisma/schema.prisma

# 2. Create and apply migration (dev)
npm.cmd run prisma:migrate --workspace=backend -- --name <descriptive-name>
# Examples: --name add-note-search-index, --name add-user-avatar-field

# 3. Regenerate the Prisma client
npm.cmd run prisma:generate --workspace=backend

# 4. Restart the backend dev server (tsx watch restarts automatically)
```

### Production migration
```powershell
# On the production server (Render), run:
npx prisma migrate deploy
```

**NEVER** use `prisma migrate dev` in production — use `prisma migrate deploy`.

## Naming Conventions

| Entity | Convention | Example |
|---|---|---|
| Model names | PascalCase singular | `Note`, `NoteTag` |
| Field names | camelCase | `authorId`, `passwordHash` |
| Enum names | PascalCase | `NoteStatus` |
| Enum values | UPPER_SNAKE | `DRAFT`, `PUBLISHED` |
| Migration names | snake_case, descriptive | `add_resource_links` |
| Indexes | `@@index([field1, field2])` | `@@index([status, updatedAt])` |

## Slug Uniqueness

```typescript
// backend/src/lib/slug.ts
export function slugify(text: string): string { /* kebab-case */ }

// backend/src/routes/notes.ts
async function uniqueSlug(title: string) {
  const base = slugify(title);
  let slug = base;
  let sequence = 2;
  while (await prisma.note.findUnique({ where: { slug } })) slug = `${base}-${sequence++}`;
  return slug;
}
```

**Always call `uniqueSlug(title)` when creating a note.** Do not manually set the slug field.

## Transaction Pattern (NoteVersion)

Every note update must atomically:
1. Create a `NoteVersion` snapshot of the **old** state.
2. Apply the update to the `Note`.

```typescript
const note = await prisma.$transaction(async (tx) => {
  await tx.noteVersion.create({ data: { noteId: old.id, title: old.title, content: old.content, status: old.status } });
  return tx.note.update({ where: { id: old.id }, data: { /* new data */ } });
});
```

## Seeding

`backend/prisma/seed.ts` creates the initial ADMIN user using credentials from `backend/.env`:
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD` (hashed with bcryptjs)

```powershell
npm.cmd run prisma:seed --workspace=backend
```

The seed script is idempotent — running it multiple times does not create duplicate users.
